# FarSense: Farsi Commonsense Dataset and Research Code

This repository packages the **FarSense** dataset and the training, inference, and evaluation scripts supplied with the project. It provides a readable directory structure, setup instructions, and a lightweight evaluator that understands the dataset's JSON answer format.

**Status:** The dataset and source files have been checked for structure, and the new validation/evaluation utility is testable without downloading any language models. This is **not yet a fully reproducible release of the paper's published model results**: trained checkpoints, original data splits, and model-generated predictions were not included in the supplied archives.

## 1. Obtain and inspect the dataset

From the repository root, extract the compressed CSV:

```bash
python -m zipfile -e data/FarSense.csv.zip data/
```

The dataset has **29,470 records**: 4,210 each for `multiple_choice`, `true_false_1`, `true_false_2`, `cloze`, `explanation`, `counterfactual`, and `cause_effect` (seven labels, covering six broad task types when the two true/false variants are grouped).

Main columns: `Paragraph_Word_Count`, `Content_Paragraph`, `Article_Title`, `task`, `prompt`, `assistant`.

`assistant` is the **reference answer** encoded as a JSON object. The multiple-choice labels mix Latin and Persian letters; the new evaluator normalizes these. Its key names confusingly end in `_predict`; that does **not** mean these are predictions generated by an evaluated model. See [data/README.md](data/README.md) for details.

The uncompressed CSV is about **168 MB**, beyond GitHub's individual file size limit. The supplied compressed archive is roughly **11 MB**, so it is included instead of the extracted CSV.

## 2. Validate the dataset (no installation required)

Python 3.9+ is recommended. Run:

```bash
python software/evaluation/evaluate.py --gold data/FarSense.csv --validate
```

This checks the task labels and parses every gold JSON answer; it does **not** generate model predictions or estimate model performance.

## 3. Evaluate your model's predictions

First obtain a CSV of **generated-only model responses** that correspond to examples in your chosen **held-out** evaluation set. For full-row-order alignment:

```csv
prediction
{"multiple_choice_question_answer_predict": "B"}
{"true_false_1_answer_predict": true}
{"true_false_2_answer_predict": false}
```

This is a format example, **not a file of model-generated results**. Your prediction CSV must contain one row per gold row in exactly the same order, **or** have a `row_index` field giving the **zero-based row position in the supplied gold CSV**, for evaluating an explicitly selected subset. A `row_index` isn't a permanent ID and only applies to the exact gold file used.

Example subset CSV (`examples/predictions_template.csv` provides empty slots):

```csv
row_index,prediction
0,"{""multiple_choice_question_answer_predict"": ""B""}"
1,"{""true_false_1_answer_predict"": true}"
```

Run the evaluator:

```bash
python software/evaluation/evaluate.py \
  --gold data/FarSense.csv \
  --predictions path/to/your_model_predictions.csv \
  --pred-column prediction \
  --output-dir results
```

Output: `results/scored_predictions.csv` (per-row diagnostics), `results/metrics_by_task.csv`, and `results/metrics_by_task.json` (per-task summaries). The lightweight tool calculates:

- **Multiple-choice / true-false:** exact-match accuracy and macro precision, recall, and F1.
- **Free-text tasks:** exact-match rate and a simple whitespace-token F1. These are diagnostic measures only, **not** BLEU, ROUGE-L, or BERTScore.
- **All tasks:** fraction of outputs that could be parsed into the expected answer type. Invalid/missing predictions count as incorrect rather than being silently dropped.

For the original research metrics and their requirements, see [software/evaluation/README.md](software/evaluation/README.md). **Do not describe the lightweight metrics as reproductions of the paper's published scores.**

## 4. Training and inference (original scripts)

To install Python dependencies used in the original training and inference code:

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

The provided scripts are located at `software/training/train.py` and `software/inference/inference_original.py`. The former uses Hugging Face `datasets` / `TRL` and expects a dataset with a `messages` field and **train/test splits**; the latter currently loads `Kamyar-zeinalipour/CS_Farsi` from Hugging Face and expects fine-tuned adapters under `outputs/`. Neither uses the uploaded `FarSense.csv` directly without preprocessing and split/model setup.

**Important limitations of the original scripts:** GPU availability, gated model access, local LoRA adapter directories, training configs and historical `transformers`/`trl`/`peft` versions may be required. The inference script includes a hard-coded CUDA device assignment and decodes the **full prompt plus the generated tokens** into its `output` column. For reliable evaluation, save only newly generated tokens in a separate `generated_text` column and align them against the correct held-out examples. The original code has been preserved rather than silently rewritten.

To run the built-in evaluator tests:

```bash
python -m unittest discover -s tests -v
```
